# phala_cvm_env (Resource)

Manages the complete environment value map of an existing CVM separately from its allocation. Declare allowed keys with phala_app.env_keys and omit env/encrypted_env on the app and instance resources. Values can then reference allocated instance identities without a Terraform dependency cycle. This resource never changes the measured key allowlist or compose revision. Cloud does not expose plaintext values for drift detection. Destroy only releases Terraform ownership; it does not erase the CVM environment or delete/restart the CVM. Set env = {} explicitly to clear values.

## Example Usage

```terraform
resource "phala_app" "coordinators" {
  name           = "coord-0"
  members        = ["coord-0", "coord-1", "coord-2"]
  size           = "tdx.small"
  docker_compose = file("coordinator.yaml")
  env_keys       = ["BROKERS", "ORDINAL"]
  wait_for_ready = false
}

resource "phala_app_instance" "coordinator" {
  for_each = toset(["coord-0", "coord-1", "coord-2"])

  app_id            = phala_app.coordinators.app_id
  name              = each.key
  wait_for_ready    = false
  wait_for_identity = true
}

resource "phala_cvm_env" "coordinator" {
  for_each = toset(["coord-0", "coord-1", "coord-2"])

  cvm_id = phala_app_instance.coordinator[each.key].vm_uuid
  env = {
    BROKERS = jsonencode([
      for peer in phala_app_instance.coordinator :
      "https://${trimprefix(peer.instance_id, "0x")}-7000.${peer.gateway_base_domain}"
    ])
    ORDINAL = trimprefix(each.key, "coord-")
  }
}
```

## Ownership and lifecycle

`phala_app.env_keys` owns the measured allowlist; `phala_cvm_env.env` owns
the complete value map. Omit `env` and `encrypted_env` on the allocation
resources, including the adopted bootstrap slot. Never declare two value
owners for one CVM. Changing allowlisted keys remains a measured app-compose
change, with the normal KMS and revision-rollout requirements.

The provider waits for any existing Cloud operation to finish, validates
every key against the current allowlist, encrypts values using the CVM's
environment public key, and submits a value-only update. It never writes
`env_keys` or reconstructs the compose manifest. Optional readiness waits
for a running CVM with no operation in progress, not application health.
Independent CVM resources run concurrently under Terraform's parallelism.

Plaintext exists in Terraform state. Protect the state backend. Cloud does
not expose plaintext for readback, so this resource cannot detect external
value edits. It does detect a deleted CVM; changing `cvm_id` replaces only
the environment binding, not the CVM.

Destroying this resource releases ownership without clearing values or
restarting/deleting the CVM. To clear values on a retained CVM, apply
`env = {}` before removing the binding.

## Migration from inline values

In one configuration change, replace the app's inline `env` with the same
explicit `env_keys`, remove per-instance inline values, and add environment
resources for every retained CVM. Keep app/slot addresses and placement
unchanged. The allocation resources relinquish value ownership without
erasing the existing payload; the new resources configure it in place.
Review the plan to confirm no CVM replacements are proposed.

## Schema

### Required

- `cvm_id` (String) Target CVM identifier, usually phala_app_instance.vm_uuid.
- `env` (Map of String, Sensitive) Complete plaintext environment map. Encrypted before API submission, but stored in Terraform state. All keys must already be allowed by the measured app compose. Do not manage the same CVM's values in another resource.

### Optional

- `wait_for_ready` (Boolean) Wait for the CVM to be running with no operation in progress after the environment update. This is CVM readiness, not application health.
- `wait_timeout_seconds` (Number) Timeout for waiting for an existing operation and optional post-update readiness.

### Read-Only

- `id` (String) Environment resource ID, equal to cvm_id.
- `status` (String) Current CVM status.
