# phala_cvm_env (Resource)

Manages an existing CVM's environment values separately from allocation, without changing the measured key allowlist or compose revision.

## Example Usage

```terraform
resource "phala_app" "coordinators" {
  name           = "coord-0"
  members        = ["coord-0", "coord-1", "coord-2"]
  size           = "tdx.small"
  docker_compose = file("coordinator.yaml")
  env_keys       = ["BROKERS", "ORDINAL"]
  wait_for_ready = false
}

resource "phala_app_instance" "coordinator" {
  for_each = toset(["coord-0", "coord-1", "coord-2"])

  app_id            = phala_app.coordinators.app_id
  name              = each.key
  wait_for_ready    = false
  wait_for_identity = true
}

resource "phala_cvm_env" "coordinator" {
  for_each = toset(["coord-0", "coord-1", "coord-2"])

  cvm_id = phala_app_instance.coordinator[each.key].vm_uuid
  env = {
    BROKERS = jsonencode([
      for peer in phala_app_instance.coordinator :
      "https://${trimprefix(peer.instance_id, "0x")}-7000.${peer.gateway_base_domain}"
    ])
    ORDINAL = trimprefix(each.key, "coord-")
  }
}
```

## Ownership and lifecycle

Declare measured keys with `phala_app.env_keys`; omit `env` and `encrypted_env`
on app/instance resources, including the adopted bootstrap slot. Each CVM
must have one value owner. Changing allowed keys remains a measured compose
change subject to KMS and revision-rollout requirements.

Updates wait for the target's existing operation, validate keys, and encrypt
values with its environment public key. They never write `env_keys` or
reconstruct the manifest. Independent targets update concurrently; readiness
means a running CVM with no pending operation, not application health.

Protect Terraform state: it contains plaintext values. Cloud does not expose
plaintext readback, so external value edits cannot be detected.

Destroy releases ownership without clearing values or restarting/deleting
the CVM. Apply `env = {}` to clear retained values. Changing `cvm_id` replaces
only the environment binding.

## Migration from inline values

Replace inline values with the same explicit app `env_keys` and one
`phala_cvm_env` per retained CVM. Omission relinquishes inline ownership
without erasing values. Keep resource addresses and placement unchanged;
review the plan to confirm no CVM replacements.

## Schema

### Required

- `cvm_id` (String) Target CVM identifier, usually phala_app_instance.vm_uuid.
- `env` (Map of String, Sensitive) Complete environment map. Keys must already be allowed by the measured app compose. Encrypted before submission; plaintext remains in Terraform state.

### Optional

- `wait_for_ready` (Boolean) Wait for the CVM to be running with no operation in progress after the environment update. This is CVM readiness, not application health.
- `wait_timeout_seconds` (Number) Timeout for waiting for an existing operation and optional post-update readiness.

### Read-Only

- `id` (String) Environment resource ID, equal to cvm_id.
- `status` (String) Current CVM status.
